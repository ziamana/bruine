## 2. Errors must say what to do
Map dsh/pi-ai errors to one red line + one dim hint line:
| Cause | Message | Hint |
|---|---|---|
| connection refused / DNS / TRANSPORT | `Can't reach your model server at <baseURL>` | `Is llama.cpp / Ollama / LM Studio running?  Change it: kumo setup` |
| timeout | `The model server did not answer in time (<n>s)` | `It may still be loading the model. Try again, or check the server logs` |
| 401 / 403 | `The API key was refused by <provider>` | `Set a new key: kumo setup` |
| 404 model | `Model "<id>" not found on <baseURL>` | `Available: <first 3 ids from /v1/models>. Change it: kumo setup` |
| context overflow | `The conversation is larger than the model's context (<n>k)` | `Use /compact or /new` |
| 429 | `Rate limited by <provider>` | `Wait a moment and try again` |
| 5xx | `The model server returned an error (<code>)` | first line of its message |
Never a stack trace in the UI; full detail in `$DSH_HOME/logs/kumo.log`.
