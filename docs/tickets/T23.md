## 1. No emoji anywhere
- Remove `💭` and any other emoji from the UI. Allowed: plain Unicode symbols (`✓ ✗ ● · ✢ ✺ ✶ ✻ ✽ ⠋ ⎿ │ ∴`, all checked NOT Extended_Pictographic; ✳ U+2733 is, so it is banned) with the
  existing ASCII fallback (`KUMO_ASCII=1`).
- **Animated spinner** (pi-tui `Loader` or own, ~80-120 ms per frame) wherever something is in progress:
  frames `· ✢ ✺ ✶ ✻ ✽ ✻ ✶ ✺ ✢` (ASCII: `- \ | /`).
  - reasoning running: `<spinner> Thinking  <sentence>`
  - tool running: `<spinner> bash  git status`
  - done: reasoning → `∴ Thought for 4.1s` (dim); tool → `✓` green / `✗` red.
- The spinner must stop and never leave a frame on screen after Escape, error or end of turn.

## 2. Reasoning sentence by sentence
Today the line grows token by token. Wanted: **only complete sentences are shown, each one replaces the previous one.**
- Buffer the reasoning. A sentence is complete at `\n`, or at `.` `!` `?` `…` followed by a space (not inside a number
  like `3.5`, not after `e.g`/`i.e`).
- Show the LAST complete sentence, whole. The sentence being written is not shown.
- Before the first sentence completes: `<spinner> Thinking`.
- Sentence longer than the width: cut at the end with `…` (never scroll the text sideways, never show the left `…`).
- Note: dsh's web UI (`ReasoningRow`, `latestLine`) shows the line being written. kumo deliberately differs.

## 3. Spacing ("everything is stuck together")
- One empty line between every block: user prompt, reasoning, each tool call, assistant text.
- 2-column left padding for everything in the chat. Tool output indented under its header with a dim `⎿` on the first
  line, like:
  ```
  ✓ bash  git status  0.4s
    ⎿ On branch master
      nothing to commit
      … 3 more lines
  ```
- User prompt: dim `›` + text, with an empty line after it.
- Editor box and footer: one empty line above the editor.

## 4. Bugs seen on Aron's screen
- Tool headers show `…` instead of the argument (`✓ bash  …`, `✓ read  …`). Show the command / path / pattern
  (first 60 cells, cut with `…`). The piped mode already does it right (`● read  note.txt`).
- Footer: ALWAYS show the mode: `ask` muted, `auto` sky, `FULL ACCESS` bold rose, and `plan` lavender when Plan is on.
  (Updated 2026-10-02: the badges are colored words drawn through palette roles, not SGR dim/yellow/red and not
  filled chips, in the three-row status bar. What this ticket protects is unchanged: the mode is always on screen,
  and `ask` reads as the quiet, inactive state. `test/e2e/terminal.test.ts` asserts the roles.)
  The T22 test marked `it.fails` must now pass (remove `.fails`).
