## 1. Never echo the API key (security)
`io.question(keyPrompt)` uses readline, so the key is printed in clear while typed
(it stays in the terminal scrollback and in any screen recording).
- Add `SetupIO.secret(prompt): Promise<string>` : raw mode on stdin, print `*` per char, handle Backspace, Enter, Ctrl+C (exit 130).
- Use it for the API key. Non-TTY: read one line from stdin without echo.
- Test: a fake IO whose `secret` is called for the key and `question` is NOT called for it.

## 2. `--help` / `--version` only as the FIRST argument
Today `kumo "explain the --help flag"` prints the usage instead of asking the model.
- Intercept only when `argv[0]` is `--help`, `-h`, `--version`, `-V`.
- Test both cases.

## 4. Let the user type a server address (found in the first real run, 2026-09-25)
The simple setup only probes 127.0.0.1. On a real home setup the model runs on ANOTHER machine,
so the user ends up with only "DeepSeek / OpenRouter" and no way to use their own server.
- When nothing answers locally, the menu becomes:
  `1) Enter a server address   2) DeepSeek   3) OpenRouter   [1]`
- Option 1: ask `Server URL (e.g. http://192.168.1.64:8081):`, normalise (add `http://`, add `/v1` if missing),
  `GET /v1/models` with a 3 s timeout, list the models, let the user pick one, write the same settings as a local hit.
- Test: a fake server on a random port, answered through the "enter an address" path.
