# T37 — `/model`: switch provider and model without leaving the session

Aron (2026-09-26), using kumo against a local llama.cpp server: *"est ce qu'il y a un /provider qui
affichent toutu les provider qwen cloud gpt claude api openrouter ?"*. There is none. The route is
chosen by `kumo setup` and by hand-editing `~/.kumo/settings.yaml`; a user who wants to compare two
models restarts kumo, and `/effort` (T34) is the only runtime model control.

OpenCode solves this with `/models` (a dialog of every model) and `ctrl+a` (a dialog of every
provider), fed by a models.dev catalog cached at `~/.cache/opencode/models.json`. kumo must not copy
that: the catalog would be a 4.9 MB JSON that goes stale, and a local llama.cpp server is the real
source of truth. **dsh's `llm` runtime already is the catalog**, and it is local-first.

## Mechanism (verified in dsh 0.1.5-rc.3, no new dependency)

| Need | dsh API |
|---|---|
| mounted routes | `llm.listProviders(): LlmProviderInfo[]` (`{id, name}`) |
| declared-but-unmounted routes | `llm.listConfigurableProviders(): LlmConfigurableProvider[]` |
| what one route serves now | `llm.listModels(provider): Promise<LlmModelInfo[]>` (pi-ai asks the server's `/v1/models`) |
| context window + efforts | `llm.resolveModelInfo(provider, model)` |
| persist the choice | `agentDefaultModel.saveSelection({provider, model})` → writes `agent-default-model` in settings.yaml |
| switch the live route | replace `.current` on the selection ref — **the seam kumo-effort already uses** (T34) |

`dsh-agent` `installModelSelection` reads `.current` per request, overrides `provider`/`model` on
`agent/request`, and appends its own durable `[model changed: …]` user notice on `agent/pre-step`
(`model-selection.js:12-27`). That notice is the cache-safe mechanism (ARCHITECTURE §0: never rewrite
the prompt, append at the end). kumo writes no YAML: `saveSelection` is dsh's own writer.

## 1. A new plugin `src/plugins/model.ts`, shaped like `effort.ts`
`name`, `KUMO_MODEL_SERVICE`, a duck-typed `ModelUi`, a `ModelPicker` class with
`attach` / `handles` / `runCommand` / `rebind`, `apply(ctx)` with `ctx.inject(["kumoRepl"])` +
`commands.register` + `ctx.provide`, and `export default { name, apply }`. Mounted by kumo-repl with
`ctx.plugin?.(kumoModel)` next to `kumoEffort`, so the profile's bundle patch stays untouched.
`/model` and `/provider` go in dsh's `commands` service (that is how `/effort` reaches the T31 palette),
and kumo's slash router delegates to the service.

## 2. The picker: provider, then model
`ui.askChoice` twice, never over chat lines. `askChoice` grows an optional third argument
`{ initial?: number }` (it already had the machinery: `SelectList.setSelectedIndex`) so the cursor
starts on the current route and Enter alone changes nothing. Each row shows the pretty name
(`displayModel`: settings `name`, else the id without its directory and `.gguf`), the context window,
and `(current)`.

## 3. Only models the route DECLARES are offered
`dsh-llm-pi-ai` resolves a route through the profile's configured models and throws
`LlmError("pi-ai provider ... has no configured model ...", "UNKNOWN_MODEL")` otherwise
(`lib/index.js` `modelOf()`). Measured on the e2e harness: switching to a model the server advertises
but settings.yaml does not declare produced `✗ pi-ai provider "local" has no configured model`. So
**the model list is settings.yaml's `providers.<id>.models[]`**, and a model the server serves but
kumo never recorded is *named* in a notice with the fix in one command (`run kumo setup to add them`),
not offered as a switch that breaks the next turn. `/model <provider>/<model>` refuses it the same way,
at the command, not at the next request.

## 4. `/model <provider>/<model>` sets directly
The provider is resolved against the known ids, **longest first**: model ids carry slashes of their own
(`openrouter/qwen/qwen3-32b`), so `split("/")` is wrong. An unknown provider is refused, naming what is
configured. Non-TTY: the same facts as one line per provider, then the `/model <route>` hint.

## 5. What the switch must also get right
- The footer follows: `model`, `provider`, `modelName`, `contextWindow` from the new route's entry, and
  `contextUsed: 0` (the old model's context is not this model's context).
- `KumoUi.resetRouteCache()`: `#cachedHost` is memoized, so the header would keep showing the old host.
- The reasoning effort follows: a live effort the new model still offers is kept, one it does not offer
  is dropped (`Effort.adoptRoute`, T38), and the effort plugin's cached levels are re-resolved.

## Acceptance
- Unit: `parseRouteArg` resolves the longest known provider, so `openrouter/qwen/qwen3-32b` is one
  route; an unknown provider is refused by name.
- Unit: the picker marks the current provider and model, starts the cursor on them, and Esc at either
  step changes nothing (`holder.current` identity untouched, `saveSelection` never called).
- Unit: a model the route does not declare is refused by `apply`, `holder.current` is untouched, and
  no kumo.json is written.
- Unit: the switch replaces the selection object (not mutates it), keeps a still-valid effort, drops an
  invalid one, sets the footer from the new route's entry with `contextUsed: 0`, and calls
  `resetRouteCache`.
- E2E (recording fake server, 2 declared models): `/model` → down → Enter → the next recorded body has
  `model: "e2e-model-2"`, the footer shows the new model's own window, the system+developer message
  **content** and the `tools` array are byte-identical to the previous turn, and dsh's
  `[model changed: …]` notice is in the history. The wire role label may change (`developer` → `system`)
  because that is pi-ai's per-model convention, not kumo editing the prompt.
- E2E: `/model local/never-loaded` is refused in the session, and no request is sent for it.
