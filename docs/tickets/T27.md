# T27 — kumo's signature UI: the local model dashboard

Positioning: kumo is the terminal agent for people who run their OWN models. Show what they care about and what
Claude Code / Codex cannot show (they have no local server). Decided with Aron 2026-09-25. Do after T25.

Target look (100 columns):
```

  › explain this folder

  ✻ Thinking  I will look at the project structure first

  │ ✓ read   src/bin.ts             0.2s
  │ ✓ grep   "export"  14 matches   0.1s
  │ ✓ read   +3 files               0.4s

  The folder contains kumo's launcher and…

  ✓ 5 tools · 41s · 1.2k tokens
 ask   ctx 12% of 100k   52 tok/s   pp 1.1k/s   cache 97%
```

## Files
`src/ui/**`, `src/plugins/render.ts`, `src/render/**`, `test/**` (new tests, update assertions, never delete),
`test/e2e/**`.

## 1. Cache meter (the most important part)
Share of the prompt the server REUSED instead of recomputing, for the last LLM call: `cache 97%`.
- Data (verified by BOS on llama.cpp, 2026-09-25): the final stream chunk has
  `usage.prompt_tokens_details.cached_tokens`; pi-ai maps it to `cacheRead` and dsh-llm-pi-ai to
  `usage.cacheReadTokens` (dsh-llm-pi-ai/lib/index.js ~1362). First check with a real capture whether dsh's
  `inputTokens` includes or excludes the cached part, then: `cache% = cached / total prompt tokens`.
- Colors: ≥ 80 % green, 30-79 % yellow, < 30 % red, but the FIRST call of a session is always gray (nothing to reuse
  yet, not a failure).
- Unknown (server gives no cached count): hide the item, never show `0%`.
- Footer order: `<mode> <plan>  ctx …  tok/s  pp …/s  cache …%` then model (T25 layout, extended).

## 2. Tool rail and grouping
- Every tool line of a turn is prefixed by a vertical rail `│` in the chat's left padding. Rail color: blue for tools,
  red on the line of a failed tool. Reasoning and text have no rail.
- Consecutive successful calls of the same tool with no text between them collapse after the 2nd one into
  `✓ read   +3 files   0.4s` (sum of durations). `ctrl+o` toggles expanded / collapsed for the whole chat.
- Failed calls are never collapsed.
- Aligned columns: tool name padded to 7 cells, duration right-aligned.

## 3. Turn summary
At the end of each turn (not on Escape, not on error): one dim line `✓ 5 tools · 41s · 1.2k tokens`
(tools of the turn, wall time from Enter to end, output tokens of the turn; `1.2k` format above 999). No tools:
`✓ 12s · 340 tokens`. Escape: `· cancelled after 12s`.

## 4. Header and startup animation
- Header: `kumo  ·  <model name>  ·  <host of the base URL, or provider name for cloud>` (+ version dim at the end).
- On startup only, when stdout is a TTY and not `KUMO_ASCII`: the word `kumo` drawn with block/braille characters
  "forms like a cloud" in 6 frames over ~500 ms, then is replaced by the normal header. No emoji (strict test from T23
  stays). Skipped entirely when piped, in CI (`CI=1`), or with `KUMO_NO_ANIMATION=1`.

## Acceptance
- Unit: cache% from a usage with cached 9700 / total 10000 → `97%`; first call gray; no cached field → hidden.
- Unit: 4 consecutive reads → 2 lines + `+2 files`; a failed read in the middle breaks the group.
- E2E: screen of a turn with 4 reads + 1 failed grep, collapsed and expanded (ctrl+o); footer with cache; summary line.
- Manual (report output): one real turn against 192.168.1.64:8081, second prompt shows `cache` ≥ 80 %.

## 5. Paste chip (added 2026-09-25, Aron liked OpenCode's)
pi-tui's Editor ALREADY collapses a paste of > 10 lines or > 1000 chars into `[paste #1 +22 lines]` and expands it on
submit (`editor.js` `submitValue` → `expandPasteMarkers`). Make it look like a chip: render the marker with the accent
background and dark text (`[Pasted 22 lines]`), and in the chat echo of the user message keep the chip instead of
dumping the 22 lines. The text sent to the model is unchanged (full paste).
