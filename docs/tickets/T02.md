# T02 — `kumo` launcher

## Goal
`kumo [args]` starts dsh with kumo's own home and profile.

## Files
- `src/bin.ts` (replace placeholder)
- `src/launch.ts`
- `test/launch.test.ts`

## Spec
- `src/launch.ts` exports `buildLaunch(argv: string[], env: NodeJS.ProcessEnv, home: string)` returning
  `{ command: string, args: string[], env: Record<string,string> }` — **pure, no side effects**:
  - `command`: `"dsh"`
  - `args`: `["--profile", "kumo", ...argv]`
  - `env`: copy of `env` with `DSH_HOME` = `env.KUMO_HOME ?? join(home, ".kumo")`
- Special cases handled in `bin.ts` BEFORE spawning:
  - `kumo --version` / `-V` → print `kumo <version from package.json>`, exit 0
  - `kumo --help` / `-h` → print usage (English), exit 0
- `bin.ts` spawns with `child_process.spawn(command, args, { env, stdio: "inherit" })` and exits with the child's code.
- If `dsh` is not found (spawn error ENOENT): print `kumo: DeepSeek Harness (dsh) not found. Install it: npm i -g @deepseek-ai/dsh` and exit 1.

## Acceptance (test/launch.test.ts)
- default home → `DSH_HOME` ends with `/.kumo`
- `KUMO_HOME=/tmp/x` → `DSH_HOME` is `/tmp/x`
- argv `["fix the tests"]` → args `["--profile","kumo","fix the tests"]`
- original env keys are preserved (e.g. `PATH`)
