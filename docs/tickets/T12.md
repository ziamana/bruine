# T12 — HOTFIX: reasoning lines stack up instead of replacing each other

## Bug (reproduced by BOS in an 80-column PTY, 2026-09-25)
Raw output: `...answer in one line."\r\n\x1b[22m`. A real newline is printed INSIDE the dim reasoning line,
so the next line is drawn below instead of replacing it. With real reasoning, the screen fills with 15 `💭` lines.

Cause: `ReasoningLine.push()` only handles the LAST `\n` of a delta (`lastIndexOf`). A delta like
`'line one\n\nline two'` (paragraph break, very common) leaves the first `\n` inside `finished`.

## Files
- `src/render/reasoning.ts`, `test/reasoning.test.ts`

## Fix
1. Split the delta on EVERY `\n`. The last segment continues `current`; every other segment completes a line.
   `lastFinished` = the last completed segment that is non-empty after trim.
2. Before drawing, sanitize: replace `\r`, `\t`, `\v`, `\f` and any other control char with a space.
3. Width by DISPLAY cells, not JS length: use the `string-width` package. Truncate so that
   `"💭 " + text` is at most `columns - 1` cells.
4. Wrap each draw in autowrap-off / autowrap-on: `"\x1b[?7l" + line + "\x1b[?7h"`, so the terminal can NEVER
   wrap the line even if a width is miscounted.

## Acceptance (new tests)
- `push("a\n\nb")` → no write contains `\n`; last shows `💭 b`.
- `push("first\n\n")` → shows `💭 first`, no `\n` written.
- `push("x\ty\rz")` → shown as `x y z`.
- columns = 20, text with emoji / CJK → drawn line ≤ 19 cells (string-width).
- Over a whole scripted stream of 30 deltas with mixed `\n`, `\n\n`: the ONLY `\n` ever written is the one from `end()`.
