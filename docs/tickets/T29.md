# T29 — Paste an image (after the first public release)

**Done 2026-09-26.** `src/image/`: `clipboard.ts` (readers per OS, byte sniffing,
the dsh byte ceiling), `pending.ts` (the `[Image N]` chips), `vision.ts` (settings
first, then one `/v1/models` probe, cached per route), `attach.ts` (the store call
and the user content blocks). The dsh attachment store is already in the profile:
`dsh-base` ships `@deepseek-ai/dsh-attachment-local`, so `ctx.attachments` exists
and kumo only needed the types as a direct dependency. Clipboard tools are not
installed on the dev box, so the reader is covered by injected runners, not by
spawning wl-paste.

Two decisions the ticket left open:

- The chip stays in the text part when an image really was attached (it is the
  label the user typed and the label the model reads, next to the image), and is
  stripped when none was, so a text-only model is never told about an image it
  cannot see.
- A model entry in settings.yaml that declares nothing is "unknown", not "no": the
  server's own `capabilities` decides, which is what makes Ornith work.

ctrl+v — read an image out of the system clipboard → `[Image 1]` chip in the editor (same style as the paste chip, T27.5), sent to
the model as an image attachment. dsh has `dsh-attachment` and the `read_image` tool: reuse them.
- Clipboard read per OS: Linux `wl-paste --type image/png` (Wayland) or `xclip -selection clipboard -t image/png -o`;
  macOS `osascript` / `pngpaste`; Windows PowerShell `Get-Clipboard -Format Image`. Missing tool → one dim line
  explaining what to install, never a crash.
- Only if the main model declares vision (settings, or llama.cpp `/v1/models` `capabilities` contains `multimodal`:
  Ornith does). Otherwise: notice `This model cannot see images` and nothing is attached.
- Also: dragging an image file path into the terminal (`/path/x.png`) is offered as `[Image 1]`.
