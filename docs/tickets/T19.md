# T19 — Gate follow-ups + the judge must really work on local models

## A. The judge probably never answers on a local model (BOS, code reading, 2026-09-25)
`judge.ts` sends `reasoningEffort: "off"`. In dsh-llm `resolveCallWithInfo` (dsh-llm/lib/index.js ~2117):
- model with **no** `reasoningEfforts` declared (this is what kumo's setup writes for local servers) and a requested
  effort → throws `UNSUPPORTED_REASONING_EFFORT`;
- model whose efforts do not include `off` → same throw.
`askJudge` catches → ASK. **Result: Auto silently behaves like Ask**, the bug T18 meant to fix, by another path.

### Fix
1. Send `reasoningEffort: "off"` ONLY if the route's model info lists `off`; otherwise omit it.
2. Setup: for an OpenAI-compatible local server, write `reasoningEfforts` for the model with an `off` level so
   thinking models (Qwen, Ornith) can be judged without reasoning.
3. When the judge fails (error, timeout, empty), show ONE dim line per session:
   `auto: judge unavailable (<short reason>), asking instead`. Never silent.

### Acceptance
- Unit: model info without `off` → request has no `reasoningEffort`.
- **Real test (manual, report the output):** with `~/.kumo` pointing at http://192.168.1.64:8081/v1 (Ornith),
  Auto mode, ask the agent to run `python3 -c "print(1)"` → the judge answers (ALLOW or ASK) in < 5 s,
  and no "judge unavailable" line. Paste the terminal output in the report.

### Fix
- git: parse global options first (`-C <dir>`, `-c <k=v>`, `--git-dir`, `--work-tree`) then read the sub-command.
  Any `-c` → ask. `log`/`show`/`diff` with `--output` → not read-only.
- find: disqualify any option starting with `-exec`, `-ok`, `-fprint`, `-fls`, `-delete`.
