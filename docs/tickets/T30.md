# T30 — Update check + `kumo update` (MUST ship in the first public release)

Without it, the first users never learn that a new version exists. Decided with Aron 2026-09-25.

## Behavior
- At startup, in the background (never delays the UI): `GET https://registry.npmjs.org/kumo-code/latest`
  (2 s timeout), at most once per 24 h, result cached in `$DSH_HOME/update-check.json` `{ checkedAt, latest }`.
- If `latest` > current (semver): one notice line above the editor (T24 notice style, stays until the first prompt):
  `kumo 0.3.0 is available (you have 0.2.0). Run: kumo update`
- `kumo update`: detect how kumo was installed from the real path of the running binary
  (npm global prefix, pnpm global dir, bun, or a git checkout / `link:`), then show the exact command and ask
  `Update now? (y/N)`:
  - npm: `npm install -g kumo-code@latest`, pnpm: `pnpm add -g kumo-code@latest`, bun: `bun add -g kumo-code@latest`
  - git checkout or link (developer install): print `Developer install: run git pull && pnpm build`, never run it.
  Run the command with inherited stdio, report the new version at the end.
- Never auto-install. Never send anything but the GET (no id, no version in headers beyond npm's default).
- Off switches: kumo.json `updateCheck: false`, env `KUMO_NO_UPDATE_CHECK=1`, and always off when `CI` is set or
  stdout is not a TTY. Setup: add the toggle to the Telemetry step screen (default on, it sends no data).

## Files
`src/update.ts` (new), `src/bin.ts` (`kumo update`, background check), `src/ui/kumo-ui.ts` (notice), `src/setup/full.ts`
(toggle), `test/**`.

## Acceptance
- Unit with a fake registry: newer → notice text exact; same or older → nothing; registry down → nothing, no error.
- Unit: checked less than 24 h ago → no request.
- Unit: install-kind detection for npm / pnpm / bun / link paths (posix and win32 paths).
- `KUMO_NO_UPDATE_CHECK=1` → zero requests.
