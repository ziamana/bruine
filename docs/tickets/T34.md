# T34 — Reasoning effort that really works + preserved thinking (measured by BOS, 2026-09-25)

## Findings on the real server (Ornith 1.5 9B, llama.cpp, recording proxy)
1. **Effort is never sent.** Request keys: `model, messages, stream, stream_options, store, max_completion_tokens,
   tools`. No `chat_template_kwargs`, no `reasoning_effort`. The footer says `effort off` while the model thinks
   (`Thought for 0.9s`): the footer lies. The T19 setup writes `reasoningEfforts { off, low }` whose wire values do
   nothing on llama.cpp.
2. **Thinking is already preserved** for Ornith: kumo (pi-ai) sends `reasoning_content` back on every past assistant
   message, and Ornith's template renders `<think>…</think>` for all of them. Good for the prompt cache (the prefix
   never changes). But Qwen 3.6+ templates strip old thinking unless `chat_template_kwargs.preserve_thinking: true`,
   which would change the prefix between turns and break the cache.
3. Each template supports different switches. Ornith's template (from `/props` `chat_template`): `enable_thinking` only
   (on/off). Qwen 3.8: `reasoning_effort` inside `chat_template_kwargs` (low/medium/high/xhigh; BOS journal 15/09:
   `xhigh` produces empty answers, never default to it).

## Mechanism (already in pi-ai 0.85, passed through by dsh-llm-pi-ai `compat`)
`compat.thinkingFormat: "chat-template"` + `compat.chatTemplateKwargs`, values resolved per request
(`openai-completions.js` `buildChatTemplateValues`): `{ $var: "thinking.enabled" }` → true/false;
`{ omitWhenOff: true }` → the effort mapped through the model's `thinkingLevelMap`, omitted when off;
a plain value is sent as is. Find the exact settings.yaml shape in dsh-llm-pi-ai (`compatGate`, ~line 420).

## Do

   `reasoning_effort`, `preserve_thinking`, `thinking_budget`. Write per model:
   - `compat.thinkingFormat: chat-template`
   - `chatTemplateKwargs`: `enable_thinking: {$var: thinking.enabled}` if supported;
     `reasoning_effort: {omitWhenOff: true}` if supported; `preserve_thinking: true` if supported (cache rule).
   - `reasoningEfforts`: `off` + `on` when only enable_thinking; `off, low, medium, high` when reasoning_effort exists
     (never `xhigh` in the list by default).
   - Ollama / LM Studio / cloud: keep pi-ai's own detection, do not force chat-template.
2. **Default effort:** `on` / `medium` for local thinking models; remembered per model in kumo.json.
3. **`/effort`** command (select of the model's levels, current marked) + shortcut `ctrl+e` cycles levels. Notice:
   `Effort: medium (next message)`. The footer shows the REAL effort sent.
4. **Cache rule:** changing effort changes only request parameters, never the system prompt or tools. It applies to the
   next request. Document in ARCHITECTURE §0 that `preserve_thinking: true` is kumo's default because it keeps the
   prefix stable, at the cost of more context (compaction handles it).
