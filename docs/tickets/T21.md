# T21 — Full setup (v0.2)

First screen of a new user. Must feel like a product, not a script.

## Entry
- First run: `Simple setup (recommended)` / `Full setup` as a pi-tui SelectList (arrows + Enter), not numbers.
- `kumo setup` re-runs the wizard at any time, pre-filled with the current values.
- Every step: `Esc` = back one step, `ctrl+c` = quit without writing anything.
- Files are written ONCE, atomically, on the final summary screen (`Save` / `Back` / `Quit without saving`).

## Steps
| # | Step | Detail |
|---|---|---|
| 1 | **Models** | a) localhost ports 8080-8090, 11434, 1234, 8000, 5000 (existing probe). b) Question: `Scan your local network for AI servers? (y/N)`. If yes: the /24 of each private IPv4 interface (10/8, 172.16/12, 192.168/16 only), same ports, `GET /v1/models`, 800 ms timeout, max 64 in flight, progress line. **Never scan a public range.** Tailscale: if `tailscale status --json` works, probe its peers' 100.x IPs (do NOT sweep 100.64/10). c) Also offer DeepSeek, OpenRouter, and `Enter a server address`. |
| 2 | **Roles** | `main` (required), `fast` (optional, used by the Auto judge; default = main), `vision` (optional). One list per role, built from step 1. |
| 3 | **API keys** | For cloud routes: `SetupIO.secret` (never echoed), then check with `GET /models` (3 s). Stored via dsh's credential provider (`$DSH_HOME/.env`, chmod 600): do NOT add a keyring dependency in this ticket. |
| 4 | **Default mode** | Ask (default) / Auto / Full access. Full needs typing `full` to confirm. |
| 5 | **Web search** | Existing step (none / SearXNG / Brave / Tavily). |
| 6 | **Skills** | Multi-select (Space toggles, Enter validates) from `skills/` shipped in the package. Chosen ones are copied to `$DSH_HOME/skills/<name>/` (dsh-skill-filesystem reads that dir, source `user-dsh`). Unchosen ones already installed are removed only if kumo installed them (keep a manifest `skills/.kumo-installed.json`). |
| 7 | **Theme** | `dark` / `light` / `high-contrast`, with a 3-line live preview (reasoning line, tool call, footer) under the list. |
| 8 | **Telemetry** | `Share anonymous usage data with DeepSeek Harness? (y/N)`, default No → `kumo.json telemetry:false`. |
| 9 | **Summary** | Table of all choices, then Save / Back / Quit. |

Not in this ticket: browser control (0.3), persistent memory (0.4). **Do not show a setting for a feature that does not exist yet.**

## Skills shipped (`skills/`)
Start with 4, each a folder with `SKILL.md` (frontmatter `name`, `description`) written for kumo, in English:
`git-workflow`, `systematic-debugging`, `code-review`, `write-tests`. Original text only: do not copy third-party skills
unless their license is MIT/Apache and the license file is kept next to them.

## Cache rule
Skills and settings are chosen at setup, loaded at session start, never changed mid-session (T17 must stay green).

## Files
`src/setup/` (split into `full.ts`, `discover.ts`, `steps/*.ts` as you see fit), `src/bin.ts`, `skills/**`,
`test/setup-*.test.ts`, `package.json` (`files` must include `skills`).

## Acceptance
- Discovery test with 3 fake servers on random localhost ports: all found, with their models.
- Test: a public IP range passed to the scanner is rejected before any request.
- Test: Esc on step 5 returns to step 4 with the previous values kept; ctrl+c writes nothing.
- Test: skills copied to `$DSH_HOME/skills`, then re-running setup and unchecking one removes only that one.
- **Manual (report the terminal output):** full setup against the real LAN finds `192.168.1.64:8081` and its model.
