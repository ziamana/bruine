# T40 — the console band: a painted bottom zone that follows the terminal's own background

## The problem
kumo deliberately renders on the **main screen** (scrollback, no alt screen, `docs/ARCHITECTURE.md`), and the Nuage
palette said it outright: "soft sky blues and lavender **on the terminal's own background**". The only painted things
were the user-prompt band and the footer pills, on hardcoded dark values.

A background was wanted, but a **full-bleed** one is structurally wrong here:

- the scrollback belongs to the terminal. Anything already scrolled off keeps the terminal's background, so painting
  every line leaves a hard horizontal seam the moment you scroll up;
- every line has to be padded to exactly `terminal.columns` or the right edge goes ragged;
- at 16 colors `surface` and `chip` fall through to the raw ANSI codes, so the prompt band painted **black** and the
  paste chips **cyan** (`\x1b[40m`, `\x1b[46m`). A real bug, visible on every 16-color terminal.

## What to build
**1. Paint the bottom zone only.** A `ConsoleBand` component (`src/ui/chat-layout.ts`) wraps the editor, the cockpit and
the footer — the three things already wrapped in `Margin` — on one surface, edge to edge, opening on a 1-column `sky`
accent that echoes the tool rail. The transcript keeps the terminal's background. The band always sits at the bottom of
the live area, so it can never show a seam. The accent spends the first of the two margin columns, so **nothing
reflows** and the user prompt still starts in column 2 (`test/e2e/terminal.test.ts` asserts exactly that).

**2. Do not hardcode the background: ask for it.** On start, query the terminal's real background with OSC 11 and
re-derive the surfaces from it (`deriveBackdrop`): on a dark terminal a cool veil just above the background, on a light
one a pale panel just below it. A terminal that never answers keeps the authored values. pi-tui already has
`queryTerminalBackgroundColor`, and it keeps swallowing the reply after the timeout, so a slow terminal cannot leak the
response into the input stream as keystrokes. `KUMO_BG=0` opts out.

**3. Fill with EL, not with spaces.** `fillLine` emits the background, the content, the background again, then `\x1b[K`:
the last cell is painted by erase-in-line and is never written, which avoids the pending-wrap state that eats or doubles
a line on some terminals. The background has to be **re-armed after every `\x1b[49m` / `\x1b[0m` / `\x1b[m`**: a nested
pill or pi-tui's reverse-video editor cursor otherwise hands the background back to the terminal default and leaves the
rest of the band unpainted.

**4. Gate every background on `bgEnabled()`** (24-bit or 256 only). At 16 colors the band renders byte for byte the
2-column margin it replaced, and the prompt band and paste chips emit no background at all, which is the bug above.

**5. The tool rail fades down its own height** (`railPaint`): `sky` to `skyDeep` (rose to deep red on failure) across the
lines of a block, so a run of tool calls reads as one gradient. At 16 colors a blended hex would collapse both ends to
the same code, so it stays flat blue/red there.

## `/reload` (added after the band shipped)
The band and the probe are startup state, so a terminal that only answers OSC 11 *after* kumo started (or a user who
edits `settings.yaml` in another window) had no way to catch up short of a restart. `/reload` re-reads in place:

- drops the memoized header host, so the header re-resolves it;
- re-reads `settings.yaml` and **compares** it with the route the session is really on. It never adopts the new route:
  the agent is bound to the one it started on, and a header advertising another would be a lie. A moved route is
  reported by name, with `/model` named as the command that moves it;
- re-probes the terminal background (OSC 11) and says whether the terminal answered.

What it is **not**: a code reload. The modules are already loaded, so a change in `src/` still needs `pnpm build` and a
restart. The command is named for what it does, and says so in its own output.

`KumoUi.reload()` returns a `ReloadReport` (`route`, `live`, `moved`, `background`) so the command line is a
presentation of a value that is already tested, and the no-lie rule is enforced in one place.

## Files
- `src/ui/palette.ts`: `bgEnabled`, `bgOptOut`, `deriveBackdrop`, `setTerminalBackdrop`, `fillLine`, `paintHex`,
  `blendHex`, the `edge` role, and `bgCode` honouring the probed surfaces.
- `src/ui/chat-layout.ts`: `ConsoleBand`, `railPaint`, the prompt band accent.
- `src/ui/theme.ts`: `chip` falls back to a plain sky when no background can be painted; `edge` added.
- `src/ui/footer.ts`: the pills go through `ansi.chipBg` (it was dead code) and the gate is `bgEnabled()`.
- `src/ui/kumo-ui.ts`: `probeBackdrop()` on start, the band wired in, `reload()` + `ReloadReport` + `routeLabel`.
- `src/plugins/repl.ts`: `/reload` in the palette, in `/help`, and its handler.
- `test/palette.test.ts`, `test/ui.test.ts`, `test/repl.test.ts`.
