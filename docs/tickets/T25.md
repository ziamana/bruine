## 1. TPS is wrong (shows 1.4, the server does 50+)
Cause (BOS, `render.ts` ~line 164): TPS is sampled ONLY on `usage` chunks. llama.cpp sends one usage chunk at the END
of each LLM call, with that call's output count. So `dt` spans prefill, tool execution and the previous call, and
`dTok` compares counts of two different calls.
Fix, per LLM call (between frame `start` and `end`):
- `t0` = time of the first `reasoning-delta` / `text-delta` / `tool-call-delta` of the call; `t1` = time of the last one.
- `n` = the call's `usage.outputTokens` when it arrives; if no usage, count deltas as an estimate (1 per delta).
- decode TPS = `n / (t1 - t0)`, shown for the LAST finished call. Live during a call: `deltas so far / (now - t0)`.
- Prefill: `pp` = `usage.inputTokens` (new tokens only if the API gives cached count) `/ (t0 - request start)`; show it
  only when > 0.
- Footer: `52 tok/s` (and `pp 1.2k tok/s` dim when available). Never copy a server-reported speed.
Test: scripted stream, 100 deltas over 2 s after a 3 s prefill, usage 100 at the end → `50 tok/s` (±5 %), not 20.
Test: two calls separated by a 4 s tool → each call's own rate.
