# T36 — kumo-bench: measure agent quality before touching the system prompt

Decision (Aron + BOS, 2026-09-26): kumo already sends DeepSeek Harness's system prompt word for word (only the identity
line differs). We only change it when a benchmark proves the change helps. **Ornith 9B is for fast iteration only;
the verdict comes from Qwen 3.8 27B (and Tiel-Coder 35B when possible).** A variant that helps the 9B but not the 27B is
rejected.

## What to build (`bench/`, a dev tool, not shipped in the npm package)
- `bench/tasks/<id>/`: ~20 tasks, each a tiny git repo + `task.md` (the prompt given to the agent) + `check.sh` (exit 0 =
  pass; runs the repo's tests or checks a file). Mix: 6 bug fixes with failing tests, 4 multi-file features with tests,
  3 refactors that must keep tests green, 3 "read the project and answer" (checked against an expected answer file),
  2 shell tasks (find/rename files), 2 traps (a task that must NOT delete or overwrite a file). Languages: mostly
  TypeScript and Python, one Go. Original tasks, no copied benchmark content.
- `bench/run.ts`: copies each task to a temp dir, runs kumo headless/piped with `KUMO_HOME` pointing to a bench home
  whose settings.yaml targets the chosen route, Full access mode (the bench repo is disposable), a wall-clock limit per
  task (default 10 min), then runs `check.sh`.
- Options: `--route <provider/model>` (reads that route from a given settings.yaml), `--variant <name>` (a system-prompt
  variant file in `bench/variants/`, applied through the persona / section config, never by editing dsh),
  `--repeat N` (default 3: local models are noisy), `--tasks a,b,c`, `--resume` (skip finished runs: overnight runs on a
  slow 27B must survive a crash).
- Output: `bench/results/<date>-<route>-<variant>.jsonl` (task, repeat, pass, wall s, output tokens, tool calls, errors)
  and a summary table: pass rate ± spread per variant, median time, median tokens.
- Temperature and seed fixed when the server allows it; record the server's `/props` (model, n_ctx, template hash) in
  every result file so runs on different presets are never mixed.

## Variants to prepare (do NOT judge them, just make them runnable)
- `dsh` : today's prompt (baseline).
- `verify` : + "Before saying a task is done, run the project's tests or the closest check, and report the result."
- `plan` : + "For work with 3+ steps, keep a todo_write list and update it as you go."
- `style` : + "Match the existing code style and structure; change only what the task needs."
- `all` : the three together.
Also fix the persona: `powered by {{model}}` must use the model's display name, not the file path.

## Files
`bench/**` (new), `package.json` (a `bench` script only; `bench` NOT in `files`), `cordis.patch.yml` or `src/profile.ts`
only if a variant hook is needed, `test/bench.test.ts` (unit tests for the runner logic with a fake kumo).

## Acceptance
- `pnpm bench --route local/ornith --variant dsh --tasks <2 tasks> --repeat 1` runs end to end on the real server.
- Killing the run and restarting with `--resume` skips what is done.
- The summary prints pass rate, median time and tokens per variant.
