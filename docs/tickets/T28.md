# T28 — Questions the AI asks (real UI) + suggested next prompts

## A. BUG: `ask_user_question` fails in kumo today
dsh ships the tool (`@deepseek-ai/dsh-tool-ask-user`: questions with `id`, `question`, optional `header`,
`options[{label, description}]`, `multi_select`; recommended option first with "(Recommended)"). The UI side is a
Cordis waterfall `user-questions/request` (`@deepseek-ai/dsh-user-questions`). **kumo registers no answerer**, so the
service rejects with `NO_PROVIDER` and the tool fails. Reference answerers: `dsh-client-ui-user-questions`,
`dsh-acp` (find the answer shape there, do not guess it).

### UI (pi-tui, above the editor, like the approval select)
```
  ? Choose mode                                         1/2
  Which database should I use for the cache?

  › SQLite (Recommended)   Zero setup, one file, enough for one user
    Redis                  Faster, but one more service to run
    Other…                 Type your own answer

  ↑↓ move · Enter choose · Space toggle (multi) · Esc skip
```
- Header in the accent color, `1/2` when several questions; Left/Right or Enter moves between questions.
- Each option: label + dim description, aligned in 2 columns; the first option is preselected.
- `multi_select`: `[x]` / `[ ]` checkboxes, Space toggles, Enter validates.
- `Other…` always last: turns into a one-line input for free text.
- Esc: answers "skipped by the user" (the tool gets a clear answer, never hangs). Escape a second time interrupts the turn.
- Piped / non-TTY: numbered text prompt on stdin (`1) SQLite (Recommended) …  [1]`).
- The question and the chosen answer stay in the chat as one dim line: `? Which database… → SQLite`.

## B. Suggested next prompt (ghost text)
After a turn ends, kumo proposes ONE likely next prompt as dim ghost text in the empty editor
(like fish shell autosuggestions): `  › run the tests`.
- **→ (Right arrow) or ctrl+f** accepts it (Tab stays Plan/Build). Typing anything replaces it. Enter on an empty editor
  with a suggestion does NOT send it (avoid accidental sends).
- Generated by the **fast** model (kumo.json `models.fast`, default main) with a SEPARATE request, never inside the
  main conversation (cache rule: the main history is untouched). Input: the last user prompt + the last 800 chars of the
  answer. Prompt: "Suggest the user's most likely next message, max 8 words, same language as the user. Reply with the
  message only." `maxTokens: 24`, reasoning off (T19 capability check), timeout 4 s.
- **Cancelled as soon as the user types or sends** (a local GPU must not be busy when the real request arrives).
- Setting `suggestions: true|false` in kumo.json and a setup toggle (default true). Never shown when piped.
