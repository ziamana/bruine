# T26 — "kumo reuses the skills you already have"

## Today (verified by BOS, 2026-09-25)
- dsh `skill-filesystem` auto-loads `<agentsHome>/skills` (= `~/.agents/skills`) and `$DSH_HOME/skills`, plus the
  project's `.dsh/skills` and `.agents/skills`. So kumo silently loads Aron's 8 skills from `~/.agents/skills`
  (seen in a real session: `youtube-transcript`, `make-interfaces-feel-better`). The setup never shows them.
- Skills in `~/.claude/skills`, `~/.config/opencode/skills`, `~/.pi/agent/skills`, `~/.codex/skills` are ignored.
- dsh has no per-skill on/off switch. Its config: `includeDefaultRoots`, `dshHome`, `agentsHome`, `customSkillDirs`,
  `watchFollowSymlinks` (default true).

## Design
1. kumo becomes the only source of truth for USER skills: in the kumo bundle patch, set `skill-filesystem.agentsHome`
   to `$DSH_HOME/agents` (a dir kumo never fills), so `~/.agents/skills` is no longer read implicitly.
   Project skills (`<project>/.agents/skills`, `.dsh/skills`) keep working unchanged.
   Spike first: find where dsh-base sets `agentsHome` and prove the override with `--dump-config`.
2. Every enabled skill lives in `$DSH_HOME/skills/<name>/`:
   - shipped skills: copied (T21 behavior);
   - skills from another agent: a **link, not a copy** (`fs.symlink(target, path, "junction")` on Windows, `"dir"`
     elsewhere), so editing the skill in Claude Code updates it in kumo. If linking fails, copy and say so.
   - Tracked in `.kumo-installed.json` with `{ name, kind: "shipped" | "linked", source }`. Never touch anything kumo
     did not create.
3. Setup step "Skills": one multi-select with 3 groups, each item `name  ·  description` (frontmatter, cut to width):
   - `Shipped with kumo`
   - `Found on this computer` (scan `~/.agents/skills`, `~/.claude/skills`, `~/.config/opencode/skills`,
     `~/.pi/agent/skills`, `~/.codex/skills`; a folder counts only if it has a `SKILL.md` with a `name`).
     Same name in several places: ONE item, source = first in that order, the others listed as `also in: claude, pi`.
   - Migration: on the first run of this version, every skill from `~/.agents/skills` is pre-checked (same behavior
     as before for existing users).
4. `kumo skills` command: prints the enabled skills with their kind and source (no content).
5. Privacy: only `name` and `description` are ever read for display. Never print, log or send a skill body during
   setup (some skills, like `ssh-server`, may contain server details).

## Cache rule
Skill changes apply at the NEXT session. T17 stays green unchanged.

## T26b — BOS review fix (2026-09-25): migration must not need the wizard
Found in review of c2b7d24: the `~/.agents/skills` migration only runs inside `kumo setup`. Since `agentsHome` no
longer points at `~/.agents`, an existing user who upgrades and just runs `kumo` silently loses every skill.
- At launch (bin, before dsh starts, non-interactive): if `$DSH_HOME/skills/.kumo-installed.json` does NOT exist and the
  user-home `.agents/skills` has valid skills, link them all (same `syncSkills` path, kind `linked`), write the manifest,
  and print one dim line: `kumo: kept your 8 skills from .agents/skills (manage them with kumo setup)`.
- Runs once: the manifest's existence is the marker. Never runs when the manifest exists (even empty = user choice).
- Tests: fake home with 3 skills in `.agents/skills` and no manifest → after launch prep, 3 links + manifest + the line;
  second launch → no line, nothing changed; manifest `[]` present → nothing linked.
- Files: `src/bin.ts`, `src/setup/skills.ts`, `test/t26-skills.test.ts`. Commit on branch t26.
