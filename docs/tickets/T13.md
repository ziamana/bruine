# T13 — Rebuild the UI on pi-tui (the pi look)

v0.1's readline UI is rejected (user rating 0/10). kumo must look and feel like pi.
pi's interface is a separate MIT library: **`@earendil-works/pi-tui`** (same lib pi 0.85 uses).
Read its README and pi-coding-agent's usage before coding.

## Layout (same as pi)
```
kumo v0.2.0
escape interrupt · ctrl+c clear · ctrl+d exit · / commands · ! bash
[Skills]  …        [Model] …

<chat: user messages, reasoning line, tool calls, markdown answers>

┌────────────────────────────────────────────┐
│ ▌ (editor, multi-line, history)             │
└────────────────────────────────────────────┘
12.3%/131k (auto)                    (local) Ornith 1.5 9B • low
⚡ TPS: 55.9
```

## Split in 4 tickets, one PR each
- **T13a** Shell: pi-tui app inside the `kumo-repl` plugin: header, chat container, editor box, footer. Replaces readline.
  Keys: `Escape` = interrupt the running turn (not the app), `ctrl+c` = clear editor (twice = exit), `ctrl+d` = exit.
- **T13b** Reasoning as a pi-tui component: ONE line that updates in place (logic from T12), collapses to
  `💭 thought for 4.2s`. Never more than one reasoning line on screen during a turn.
- **T13c** Tool calls as components (logic from T05) + assistant text through pi-tui's **Markdown** component
  (today `**kumo**` is printed raw).
- **T13d** Footer data: context used / window, model, reasoning effort, tokens/s (from `usage` chunks / `dsh-token-meter`).
  Approval prompt (T09) becomes a pi-tui select: `Allow once` / `Reject`.

## Acceptance
Side-by-side screenshot with `pi`: same structure. Escape interrupts a long answer within 1 s.
