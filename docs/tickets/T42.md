# T42 — Headless: `kumo -p "task"` runs one task, prints, exits

## The problem
kumo is interactive only. `kumo` opens a REPL and waits for a human forever. That makes it unusable
in three places every other CLI already works: a CI job, a git hook, and an orchestrator that wants
to call a coding agent as a subprocess. dsh ships a `headless` profile
(`dsh --profile headless "run the tests"`) and `@deepseek-ai/dsh-headless` is in the dependency
graph, so the machinery exists. kumo has to expose it **through the kumo gate**, not around it.

## 0. The hole this ticket must not open
`src/plugins/modes.ts` guards every tool with:

```ts
const current = repl;
if (current === undefined || exec.agent !== current.agent) return next();
```

The gate is keyed on the REPL. Mount a runner with no REPL and that line calls `next()`: **every
tool runs undecided**, and the sandbox is deliberately open (`cordis.patch.yml` sets
`danger-full-access`). The gate is the *only* permission layer, and the README promises it. So:

- the gate must govern the headless agent too, not just the REPL agent;
- when the decision is `ask` and there is nobody to ask, it must **deny**, never allow.

## 1. `-p` / `--print`, and `--output-format`
```
kumo -p "run the tests"                 the final answer on stdout, exit 0
kumo -p "run the tests" -p              same, repeatable prompts in one process
kumo -p "run the tests" --output-format json
kumo -p "run the tests" --output-format stream-json
```
- `text` (default): stdout is exactly the assistant's final text and nothing else. Reasoning, tool
  calls and the kumo chrome all go to stderr, so `kumo -p "…" > answer.md` is a clean file.
- `json`: one object on stdout at the end. `{"ok":bool,"text":str,"reason":"completed"|…,
  "sessionId":str,"durationMs":int,"tools":[{name,decision}…]}`.
- `stream-json`: newline-delimited JSON as it happens, one line per event, the last being the same
  object as `json`. This is what a UI or an orchestrator tails.
- The exit code is `turn/end`'s `reason.kind`: `completed` is 0, anything else is 1. Same rule
  `dsh-headless` uses.
- A prompt from stdin when `-p -` is given (`kumo -p - < task.md`), so a long task does not have to
  survive shell quoting.

## 2. What stays on
The **kumo gate**, the skills, the persona, the tools, the context window, compaction: everything
`cordis.patch.yml` composes. Headless is a different front end, not a different product. In
particular the system prompt and the tools array stay byte-identical to an interactive run
(ARCHITECTURE §0), which `test/cache/cache.test.ts` already knows how to assert.

`kumo-repl` is **not** mounted in headless (there is no line editor to run). That is a plugin, not a
tool, so the request prefix is untouched; the Cache Hunter test proves it.

## 3. The gate without a terminal
- `ask` becomes `deny` with a reason naming the way out:
  `kumo has no terminal to ask on (headless). Re-run with --permission-mode full, or
  --dangerously-skip-permissions.`
- `deny` (plan mode) stays `deny`.
- The judge is not consulted: a second model call in a headless run is latency nobody asked for, and
  its only possible answers are ALLOW or ASK, which the terminal-less rule already covers. A `judge`
  verdict becomes `ask`, which becomes `deny`.
- Every decision is still recorded in the modes log, so `-p` can report it in the JSON output.

## 4. Wire-up
The launcher parses the flags, sets `KUMO_HEADLESS=1`, and the patch gates two rows on it:
`kumo-headless` (only in headless) and `kumo-repl` (never in headless). Same mechanism as
`KUMO_TOOLS`, so the composed config stays inspectable with `dsh --dump-config`.

## Files
`src/plugins/headless.ts` (new), `src/plugins/modes.ts`, `src/plugins/ctx.ts`, `src/flags.ts`

## Acceptance
- `parseFlags` unit table: `-p`, `--print`, `-p x -p y`, `-p -`, `--output-format` with a bad value
  rejected by name, and the flags **not** claimed when they appear after `--` or as a value.
- The gate table gains: no REPL + `ask` = `deny`; the headless agent is governed (a `bash` outside
  the workspace is denied with no terminal present).
- E2E in a pty-less spawn against the fake SSE server: `kumo -p` prints the answer on stdout, exit
  0, and the text is not polluted by chrome.
- Cache Hunter still passes with the headless plugin mounted.
