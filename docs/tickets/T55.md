# T55 — the turn as the visual unit: hierarchy, a turn rule, a receipt

Direction chosen with Aron (2026-09-26): **Cockpit + editorial hierarchy**, on the **main screen** (no `ViewportTUI`
fork, so no scrollbar and no `HStack`/`VStack` — the native scrollback stays, which is what `TuiMainScreen` was chosen
for). The rejected third direction was "Météo": atmospheric motion that is not bound to state, which `operate.md`
forbids and which costs CPU on a slow SSH link.

## The one idea
**The turn.** A turn starts, streams, and ends. The band accent, the tool rail, the cockpit and the footer all hang off
it. That is state, not decoration, so it survives `animate.md`. Everything else quiets down around it (`bolder.md`:
commit, then clarify).

The plan is small because the mechanism already exists: `KumoUi.onTurnEnd` (`kumo-ui.ts:855`) already receives
`tools[]`, `wallSec`, `outputTokens`, `cancelled` and `error`, and `turnSummary()` (`tool-group.ts:75`) already renders
`4 tools - 12s - 1.2k tokens`. The receipt promotes that dim line into a designed element; it does not invent a
pipeline.

## P0 — the contrast defect (a defect, not taste)
`faint` is **2.64:1** on `surface`. WCAG AA wants 4.5:1 for text and 3:1 for borders and controls. `faint` carries the
editor border **and the help line that says how to quit** (`kumo-ui.ts:742`) and every tool duration.
- `faint` -> `#676e88` (**3.20:1**), still clearly faint.
- the help line -> `muted` (**5.10:1**); `faint` keeps only structural and decorative jobs.

## P1 — transcript hierarchy, turn rule, receipt
1. **Tool call weights**: the tool name carries the line, its argument drops to `muted`. Today `read` and `note.txt`
   have the same weight.
2. **Duration policy**: no `0.0s`. Under 0.05s prints nothing. Forty instant reads are forty meaningless durations.
3. **Block rhythm** (`chat-layout.ts`): one blank line between blocks, a thin rule plus the turn number between turns.
   Today a new turn and a new tool call weigh the same.
4. **Two-cell rail**: a per-tool glyph plus a state LED. `rail` widens from `"blue" | "red"` to a small descriptor, so
   the 16-color codes stay `\x1b[34m` / `\x1b[31m` (`test/ui.test.ts:464`).
5. **Turn receipt**: `turn 3 - 4 tools - 12s - 1.2k tok - cache 82%`, with a live turn counter in the header.

## P2 — the installed capabilities kumo never used
- `hyperlink` (OSC 8) on the paths in tool calls: survives a copy, a click opens it. For a coding agent this is the
  most useful delight available.
- `Image` + `imageFallback` for the pasted image (T29): a real inline image on kitty/iTerm2, a shortened name
  elsewhere.

## P3 — the one authored moment
`CancellableLoader` for the live state (the loader knows Esc cancels, so the motion carries state) and a single sweep
at turn end. `showWorking`/`hideWorking` (`render.ts:130-146`) is already the seam.

## P4 — polish
- `sparkline` (`dock.ts:14`) on an absolute scale with a max marker. It divides by its own max, so a steady 5 tok/s
  looks exactly like a steady 50.
- `wrapTextWithAnsi` so long answers wrap at any width.
- `TruncatedText` for tool summaries.

## Out of scope, on purpose
`ViewportTUI` and the scrollbar. Any animation not bound to state. Any colour without a role. And the startup
shimmer: it costs 840 ms on every launch and leaves no trace, so it either becomes a real welcome or it goes.

## Checks
`pnpm typecheck`, `pnpm test`, `pnpm test:e2e`. Every phase lands its failing-first test before the code.
