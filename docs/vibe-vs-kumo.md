# Vibe vs Kumo — ce que Vibe a et que Kumo n'a pas

Audit **lecture seule** du 2 octobre 2026. Sources : dépôt `/home/tu44/mistral-vibe` (HEAD `7c19608`, v2.25.8), config utilisateur `/home/tu44/.vibe/config.toml`, sortie de `vibe --help`, et `/home/tu44/projets/kumo` (`src/`, `docs/ARCHITECTURE.md`, `docs/tickets/`).

**Règle de lecture** : une affirmation n'est retenue que si elle est **citée** (`chemin:ligne` dans Vibe ou Kumo). Ce qui est déduit sans lecture du code est marqué *non vérifié*. Les numéros de ligne valent pour le HEAD cited ; les trois arbres changent en ce moment (autres agents sur Kumo).

**Deux avertissements de méthode** :

1. Une partie de Vibe n'est pas atteignable par l'utilisateur : le **Unified Harness** (`--experimental-harness`) est un runtime Rust interne, `vibe/_experimental_harness.py:39-42` le décrit comme « Requires an internal Unified Harness installation ». Le code existe dans l'arbre (`harness/core/`, PyO3, Rust 1.97.1, `harness/rust-toolchain.toml:1-4`) et beaucoup de fonctionnalités « Vibe seulement » ci-dessous n'existent que là. Je les signale par « *harness* ».
2. Kumo **n'est pas un fork** de Vibe ni l'inverse : c'est un *profil* + un jeu de plugins Cordis au-dessus de DeepSeek Harness (`docs/ARCHITECTURE.md:3-4`, `src/profile.ts:215-227`). La comparaison porte donc sur des surfaces/utilisateurs, pas sur du code partagé.

## 1. Vibe a, Kumo n'a pas

Trié par valeur pour l'utilisateur (usage réel quotidien d'un agent de code), puis effort estimé dans Kumo :**S** ≈ 1 journée, **M** ≈ 2-4 jours, **L** > 1 semaine. L'effort est estimé **non vérifié** (aucun chiffrage Kumo lu) ; il dépend entièrement du fait que Kumo doit passer par le patch Cordis de dsh plutôt que d'écrire du code libre.
