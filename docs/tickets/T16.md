# T16 — Modes: Plan / Build × Ask / Auto / Full access

Two independent switches, like every serious CLI (Claude Code, OpenCode, Codex).

## A. Agent mode — `Tab` toggles, shown in the footer
| Mode | Behaviour | dsh mechanism |
|---|---|---|
| **Build** (default) | normal work | — |
| **Plan** | read, search, web fetch, think; **no file writes, no modifying commands**. Ends with a plan the user approves → switches to Build | `plan-mode` plugin (`@deepseek-ai/dsh-plan-mode`, has a slash command and a user-reviewed exit) + sandbox `read-only` |

## B. Permission mode — `Shift+Tab` cycles, shown in the footer, default **Ask**
| Mode | Behaviour |
|---|---|
| **Ask** (default) | every command / file write asks `Allow once / Always for this session / Reject` |
| **Auto** | kumo decides: safe actions pass silently, risky ones ask (see C) |
| **Full access** | never asks. Red `FULL ACCESS` badge in the footer. Confirmation required when switching to it |

Sandbox: **off by default** (Aron's decision: commands really run on the machine, safety comes from approvals).
Mapping: `sandbox: danger-full-access` for all three; the gate is kumo's own interceptor, NOT dsh's sandbox escalation
(with the sandbox off, dsh's escalation approvals would never fire).

## ⚠️ Cache rule (see ARCHITECTURE §0)
Plan mode must NOT remove tools or change the system prompt: the tools array stays identical in Plan and Build.
Plan mode is enforced by the gate (C) refusing writes, and announced by a message appended at the end of the context
(`Plan mode is on: do not modify files or run modifying commands.` / `Plan mode is off.`).
Before using dsh's `plan-mode` plugin, check with a request capture that it does not change tools or system prompt; if it does, do not use it.

## C. The gate (the core of this ticket)
dsh exposes a pre-tool interception seam (allow / ask / deny). Reference: `@deepseek-ai/dsh-hooks-claude-code`
(PreToolUse → permissionDecision). **Spike first**: find the exact seam name in `@deepseek-ai/dsh-hook-protocol`
and write it in ARCHITECTURE.md section 2 before coding.

Auto mode decision, in order:
1. **Always allow**: read-only tools (read, search, list, web fetch), writes INSIDE the project directory.
2. **Always ask**: anything outside the project dir, `rm -r`, `sudo`, package installs, `git push`, `curl|sh`,
   network uploads, killing processes, editing dotfiles / shell config, anything touching `~/.ssh`, keys, `.env`.
3. **Otherwise**: ask the **fast model** (settings `models.fast`, fallback main) with a 1-line prompt:
   `Is this action safe and within the user's request? Answer ALLOW or ASK.` Timeout 5 s → ASK.
Every Auto decision is logged in the session (visible with `/permissions log`).

## Acceptance
- Unit tests for the rule table (≥ 20 commands, each with expected allow/ask).
- Plan mode: a write attempt is refused with a clear message.
- Full access requires a confirmation and shows the badge.
