# T41 — Publishable: a README and a package.json that is not a TODO

## The problem
`npm view kumo-code` today shows `repository: TODO_GITHUB_URL`. The package cannot be published as it
stands, and someone who lands on the npm page or the GitHub repo finds no explanation of what kumo
is. `docs/ARCHITECTURE.md` is an excellent design document and the wrong first impression: it starts
with product constraints for contributors, not with "install this and run it".

A public product for Windows, macOS and Linux (ARCHITECTURE §0) needs, before anything else:

## 1. README.md at the root
- What kumo is, in three sentences, and that it is a terminal coding agent that runs **your** models
  (a local llama.cpp server, OpenRouter, DeepSeek, anything OpenAI-compatible).
- Install: `npm i -g kumo-code` (the npm name is `kumo-code`, the command is `kumo` — T20), then
  `kumo` which runs the setup wizard on first launch.
- The three commands that exist: `kumo`, `kumo setup`, `kumo skills`, `kumo update`, plus the env
  vars from `bin.ts` USAGE (`KUMO_HOME`, `KUMO_ASCII`, `KUMO_NO_UPDATE_CHECK`).
- A short "what it does" list: live reasoning, tool calls, Plan/Auto/Full gate, `/model`,
  skills, paste an image.
- The honesty section, because it is the differentiator and it is a promise: kumo's tok/s is
  measured by kumo, not copied from the harness; kumo's own permission gate is the only permission
  layer; dsh telemetry is off unless you opt in.
- Pointers: `docs/ARCHITECTURE.md` for the design, `docs/tickets/` for the work, `LICENSE` (MIT).
- **No marketing adjectives, no badge soup, no em-dash** (the T24.1 rule applies to the README too:
  `test/style.test.ts` audits `src/` and `skills/`, the README must hold the same line).

## 2. package.json
- `repository`, `homepage`, `bugs` point at the real URL, in the
  `git+https://github.com/<owner>/kumo.git` form npm understands.
- `description` says what it is in one line, not the internal dsh relationship.
- `keywords` for npm discovery.
- The version stays `0.0.1`: the first public release is a decision, not this ticket. What this
  ticket removes is the blocker, not the choice.

## 3. The URL
`ARCHITECTURE.md` §0 fixes the npm name but not the GitHub org. This ticket uses
`https://github.com/kumo-code/kumo` as the single placeholder-free home, in **one** place
(`package.json`), and the README links to it relatively (`./docs/ARCHITECTURE.md`) so the repo is
correct whatever the org turns out to be. If the real org differs, `package.json` is the only file
to edit.

## Files
`README.md` (new), `package.json`, `docs/tickets/README.md` (the order table).

## Acceptance
- `node -e "require('./package.json')"` has no `TODO` left in any field.
- `pnpm test` green: `test/style.test.ts` must accept the README if its scope is widened, and the
  new README adds no em-dash and no emoji.
- A test asserts the three `TODO_GITHUB_URL` placeholders are gone, so they cannot come back.
