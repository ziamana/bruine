# T31 — Slash command palette + `/new` (minimum for the first release)

## 1. Typing `/` opens the command list
pi-tui already ships it: `CombinedAutocompleteProvider(commands, basePath)` in `@earendil-works/pi-tui/dist/autocomplete`
(`SlashCommand { name, description }`), used by pi. Wire it on kumo's Editor.
```
  › /
    /new           Start a new conversation
    /compact       Summarize the conversation to free context
    /plan          Toggle Plan / Build (also Shift+Tab)
    /permissions   Choose Ask / Auto / Full access
    /auto /ask /full   Switch permissions directly
    /skills        List the enabled skills
    /help          Show commands and keys
    /exit          Quit kumo (also ctrl+d)
```
- Opens as soon as `/` is the first character; fuzzy filter while typing (`/co` → `/compact`); ↑↓ move; Enter runs;
  Esc closes the list and keeps the text.
- **Tab completes the command** when the list is open. Tab no longer toggles anything (see part 4).
- Source of truth: kumo's own commands + every command registered in dsh's `commands` service (`dsh-commands`), with
  their description. No duplicate names; kumo's wins.
- Unknown command: notice `Unknown command /xyz. Type / to see the list.`, nothing sent to the model.

## 2. `/new`
- Waits for the current turn to finish or asks `A reply is running. Stop it and start a new conversation? (y/N)`.
- Flushes the current session (`sessions.flush`), creates a NEW agent with a new session id (same model, mode, plan
  state reset to Build, same skills), clears the chat, redraws the header, notice `New conversation.`
- Footer context back to 0 %, TPS reset, cache meter gray (first call).
- The old session stays on disk (a later `/resume` can use it; not in this ticket).

## 3. `/help`
Prints, in the chat (dim, not sent to the model): the command list above + the keys
(Esc interrupt, ctrl+c clear, ctrl+d exit, Shift+Tab Plan/Build, → accept suggestion, ctrl+o expand tools).

## 4. Keys and defaults (Aron, 2026-09-25: "Shift+Tab is Plan/Build in every CLI")
- **Shift+Tab = toggle Plan / Build.** Tab = no mode action (completion only).
- Permissions change only by command: `/permissions` opens a select (Ask / Auto / Full access, current one marked),
  and the shortcuts `/ask`, `/auto`, `/full`. Full access keeps its red Cancel/Enable confirmation (T24).
- **Default permission mode = Auto** for new installs (setup preselects `Auto (recommended): kumo decides, risky
  actions still ask`). Existing `kumo.json` values are kept. The hard rules (rm -r, sudo, git push, secrets…) still
  always ask in Auto: only unknown commands go to the judge.
- Notices (T24) updated: Plan on → `Plan mode: kumo reads and plans, no file changes. Shift+Tab to leave.`
- Update every test that presses Tab / Shift+Tab accordingly (update, never delete).

## T31b — BOS review on the real server (2026-09-26, ed9256a)
Palette, `/new`, Shift+Tab, `/auto`, colors: all OK for real. Three bugs survive on Aron's real install, and the e2e
harness cannot see them because it ALWAYS writes kumo.json `models.main`. Aron's home has settings.yaml only:
```yaml
llm-pi-ai:
  providers:
    local:
      baseURL: http://192.168.1.64:8081/v1
      models:
        - id: /etc/ajean/models/Ornith-1.5-9B-Q4_K_M.gguf
          name: Ornith 1.5 9B
          contextWindow: 100096
agent-default-model:
  provider: local
  model: /etc/ajean/models/Ornith-1.5-9B-Q4_K_M.gguf
```
Real screen: header `kumo · Ornith-1.5-9B-Q4_K_M · 192.168.1.64` (host OK), footer `ctx 0% of ?` at startup AND after
`/new`, and **no `Working`** between Enter and the first chunk (+0.7 s: only the prompt; the first chunk comes at +6 s).
1. The settings.yaml reader finds `baseURL` but not the model entry's `name` / `contextWindow` (list under `models`).
   Use a real YAML parser (dsh already depends on one) and match the entry by `id` = agent-default-model `model`.
2. `/new` resets the footer window to `?`: keep the window of the current route.
3. `Working`: likely the same root cause (an exception or early return in the submit path when the model info is
   partial). **Add an e2e harness mode "settings.yaml only, no kumo.json models"** and run the startup, working and
   `/new` tests in BOTH modes.

## T31c — first message latency (measured by BOS through a timing proxy)
```
1.97s  main request sent (5 070 tokens, no cache yet)
1.98s  session-title request sent at the same time
2.76-3.56s  the single llama.cpp slot serves the TITLE first
7.90s  first byte of the answer (3.9 s of prefill after the title)
```
dsh's session-title plugin fires in parallel with the first turn. On a local single-slot server it steals ~1.6 s from
the first answer. Delay the title request until the first turn has ended (or skip it for routes whose base URL is a
private/localhost address and use the first prompt as the title). Acceptance: through a recording proxy, the title
request starts AFTER the main request's END.
